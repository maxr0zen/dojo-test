# Додзё Медиа — адаптивный сайт по Figma

Локальный предпросмотр: http://127.0.0.1:5173/

## Запуск

Нужен Node.js 20.19+ или 22.12+.

Откройте терминал в папке `dojo-media`:

```powershell
npm ci
npm run dev -- --port 5173
```

Для сборки и проверки готовой версии:

```powershell
npm run build
npm run preview -- --port 4173
```

Production-файлы находятся в `dist/`. Для размещения достаточно статического HTTP-хостинга. Сайт не требует backend и не отправляет данные во внешние сервисы. Шрифты обслуживаются локально.

## Источник дизайна

Figma: https://www.figma.com/design/R8hr4MRJk0Qg1xKXchmNr6/?node-id=559-26

Начальный узел 559:26 — страница с несколькими фреймами. Использованы:

- 559:95 — Desktop / 1440, 1440×1672.
- 559:143 — Mobile / 390, 390×2232.25.
- 559:187 — Mobile / меню открыто, 390×2454.25.
- Компоненты, состояния и токены той же страницы.

Figma MCP вернул скриншот; получение контекста было заблокировано лимитом Starter. После разрешения пользователя использовать компьютер исходные данные получены из локальной копии `.fig`, сохранённой через Figma Desktop. Декодированы слои, стили, переменные, изображения и связи прототипа. Исходный файл Figma не редактировался.

Оригинальные изображения скопированы из `.fig` без изменения байтов. Иконки меню и закрытия экспортированы из исходной контурной геометрии. Используются те же семейства и начертания шрифтов: Oranienbaum Regular и Manrope Regular, локально через Fontsource. Не используются генерации, стоки и скриншот страницы в качестве реализации.

## Структура

- `src/App.tsx` — семантические секции, навигация, меню, карточки и контакты.
- `src/styles.css` — исходные токены Figma, адаптивная вёрстка и состояния элементов.
- `src/WorkshopHero.tsx` — композиция Remotion и встроенный `@remotion/player`.
- `src/motion.ts` — появления первого экрана и элементов при прокрутке; учёт reduced motion.
- `src/services/mockApi.ts` — заменяемый mock получения назначения карточки.
- `src/services/actions.ts` — выполнение навигации и адрес email.
- `public/assets/` — оригинальные изображения и иконки.
- `verification/` — скриншоты и результаты фактически выполненных проверок.

## Поведение

Якоря ведут к проектам, подходу и контактам. Мобильное меню раскрывается в потоке страницы, как в отдельном фрейме Figma; закрывается по Escape, выбору ссылки и при переходе к десктопной ширине. Скрытые пункты исключаются из Tab-навигации.

Карточка целиком является одной ссылкой. В исходном прототипе все три карточки ведут к контактам; это поведение сохранено. Mock-адаптер возвращает `#contacts` после 350 мс; на это время выставляются loading и disabled-состояния и блокируются повторные активации. После успеха фокус переводится на заголовок контактов.

Для проверки ошибки откройте http://127.0.0.1:5173/?mock=error и нажмите карточку. Появится явно демонстрационное уведомление вне потока документа. Его можно закрыть; через 6 секунд оно исчезнет само. После ошибки карточка доступна для повторной попытки. Никакие реальные запросы или отправки не выполняются.

Кнопки «Обсудить проект» и email сохраняют `mailto:hello@dojo-media.com`, заданный в Figma. Они только открывают почтовый клиент; сайт не отправляет письма. При проверке письма не отправлялись. Форм в макете нет, поэтому новые формы не добавлены.

## Анимации

Remotion используется для исходного изображения мастерской в hero: небольшое смещение на 8 px за 0.9 с. Изображение постоянно полностью непрозрачно, без высветления при появлении. Последний кадр точно возвращает изображение в статическое положение. Плеер не имеет управляющих элементов и не содержит текста, ссылок или форм. Код плеера загружается отдельным JS-чанком.

Первый экран и секции появляются с небольшим смещением и из уже читаемого состояния. Карточки появляются с коротким каскадом. Hover, focus-visible и active-состояния реализованы CSS; состояния кнопок и карточек соответствуют Figma.

Анимация Remotion приостанавливается вне видимой области и при скрытии вкладки. При `prefers-reduced-motion: reduce` плеер заменяется статичным оригинальным изображением, появления и плавная прокрутка отключаются. Изменение настройки учитывается без перезагрузки. Аудио отсутствует.

## Проведённые проверки

- `npm run build`: TypeScript и production-сборка Vite завершены успешно.
- Chrome: ширины 320, 390, 768, 1024 и 1440 px; полные скриншоты каждой версии просмотрены.
- На всех проверенных ширинах: 0 px горизонтального переполнения, нет обрезанного текста, все видимые изображения загружены.
- На 1440 px: начало проектов y=908, контактов y=1468, высота страницы 1672 — совпадает с Figma.
- На 390 px: начало проектов y=756, контактов y=1990.25, высота композиции 2232.25 — совпадает с Figma. DOM scrollHeight округляет её до 2232.
- Мобильное меню имеет высоту 222 px, как в исходном раскрытом фрейме.
- Проверены якоря, адреса mailto, все три карточки, loading/disabled, успех и ошибка mock, закрытие уведомления, hover и focus-visible, Tab и Escape.
- Двойная активация карточки до завершения mock даёт ровно один переход.
- Проверены пауза Remotion вне экрана, неподвижность кадра в паузе, возобновление и точный последний кадр.
- Проверены reduced motion, включая переключение на открытой странице, и сброс меню при изменении ширины.
- В выполненных сценариях не было ошибок JavaScript, неуспешных сетевых запросов или внешних HTTP-запросов.

Данные: `verification/checks.json`, `verification/motion-checks.json`, `verification/taste-report.json`.

## Taste-skill и осознанные исключения

`design-taste-frontend` применён для проверки скриншотов, адаптивности, состояний и движения. Выполнен `inspect.mjs` на 1440, 768 и 390 px. Ошибок FAIL после разрешённых исключений нет. Осталось одно предупреждение: инспектор считает движение 14 элементов недостаточным. Дополнительные эффекты не добавлялись ради количества.

В приоритете — точность заданного Figma, поэтому сохранены его кремовый фон, фиолетовый акцент, серый вторичный текст, подписи 12 px, eyebrow, тонкие разделители, одинаковые карточки и заголовок в четыре строки на мобильной версии. Не добавлено видео, которого нет в макете; вместо него используется анимация существующего изображения.

Субъективная финальная оценка по рубрике навыка: дизайн 8/10, удобство 8/10, выразительность 7/10, содержание 8/10; итог 7.8/10. Это оценка реализации в пределах сохранённого макета, а не основание для редизайна.

## Ограничения

Последующие правки по замечаниям: убрана белая подложка иконки мобильного меню; светлый фон изображения мастерской согласован с цветом страницы через CSS `mix-blend-mode: darken`. Это применяется и к Remotion, и к статичному состоянию. Оригинальный файл изображения сохранён без изменений. Скриншоты правок: `verification/hero-background-fixed.png` и `verification/hero-background-mobile-fixed.png`.

Промежуточные ширины адаптированы самостоятельно: отдельного планшетного фрейма в локальном файле нет. При ширине до 900 px используется мобильная композиция с максимальной шириной содержимого 600 px. При 901–1279 px уменьшается типографика и сохраняются три карточки в ряд. На 320 px заголовок контактов переносится в две строки.

Автоматического пиксельного diff со скриншотом Figma в исходном разрешении не выполнялось: доступны проверка точной геометрии слоёв и визуальная сверка. Проверки проводились в Chrome на Windows; Safari и Firefox не проверялись. Vite выводит информационное предупреждение об игнорировании директивы `use client` внутри `@remotion/player` в клиентской сборке; сборка и браузерные проверки проходят.
